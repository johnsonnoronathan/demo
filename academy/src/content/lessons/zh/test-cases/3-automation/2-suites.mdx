只有当大家信任测试套件、并且能在其中找到方向时，它才有用。把它塑造成金字塔，追溯到需求，并清除其中的噪音。

## 金字塔

- **单元测试**：一个函数或类，不涉及网络或数据库。毫秒级。数以百计。
- **集成测试**：几个真实的部件组合在一起，例如购物车和它的数据库。数量较少。
- **端到端测试**：像顾客一样通过浏览器操作整个应用。只有少数几个，用于关键流程。


把每项检查尽量放在最低的层级。第 2.1 课中的边界规则属于单元测试；“顾客可以买到一本书”则属于顶层。

## 追溯矩阵

维护一张“需求 → 测试用例”的表，或者给测试打上需求 ID 标签并自动生成这张表。检查它时关注两件事：没有用例的需求（遗漏），以及没有需求的用例（孤儿用例）。

## 保持健康

- **命名：** 描述行为。失败的测试名读起来应该像一个缺陷标题。
- **不稳定的测试：** 隔离只是最后手段；找到原因（时序、共享数据、顺序依赖）并修复它。
- **责任归属：** 需求变化时，相应的测试用例在同一个 pull request 中一起修改。
- **精简：** 删除与其他用例重复的用例，以及测试已移除功能的用例。
