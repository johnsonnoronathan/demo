    Effect 1 · .sk-pulse

    Pulse and cross-blur

    Bones breathe from full to half opacity. When the data lands, skeleton and content swap in one 400 ms cross-fade with a shared 2 px blur, in the same grid cell, so nothing moves.

    Use forRows and cards that one request fills. The default.

    1. Skeleton pulses while waiting
    2. Data arrives, rows mount hidden
    3. reveal(): cross-blur swap
    How the skill wires it
    <ul class="feed sk-pulse is-loading" aria-busy="true">
  <li class="sk-swap">
    <div class="sk-skeleton row-layout" aria-hidden="true">…bones…</div>
  </li>
</ul>

// data arrives: content joins each slot, then
slot.insertAdjacentHTML("beforeend",
  `<div class="sk-content row-layout">${row}</div>`);
await reveal(list);   // 400 ms
list.querySelectorAll(".sk-skeleton").forEach((s) => s.remove());

    Effect 2 · .sk-sweep + syncSweep()

    Synced shimmer sweep

    One 105° band crosses the whole page instead of restarting in each bar: every bone paints the same page-sized gradient, offset by its own position. Then the blocks rise in reading order, 60 ms apart.

    Use forArticles, docs and product pages that load in one payload.

    1. One band sweeps the page while waiting
    2. Data arrives, blocks mount hidden
    3. reveal(): blocks rise top to bottom
    How the skill wires it
    const sync = syncSweep(article);   // measures bone offsets

// data arrives: each block gets its content, then
block.insertAdjacentHTML("beforeend",
  `<h1 class="sk-content">${title}</h1>`);
await reveal(article);   // (blocks − 1) × 60 + 500 ms
article.querySelectorAll(".sk-skeleton").forEach((s) => s.remove());
sync.disconnect();

      Effect 3 · .sk-ripple + syncRipple()

      Ripple wave

      Each bone flashes on a delay of 1.1 ms per pixel from the top-left corner, so a crest rolls diagonally through the grid. Cards then pop in nearest-first, with a slight overshoot.

      Use forGrids of similar items: products, photos, results.

      1. A crest rolls through the grid while waiting
      2. Data arrives, cards mount hidden
      3. reveal(): cards pop in by distance
      How the skill wires it
      const sync = syncRipple(grid);   // distance of every bone

// data arrives: each slot gets its card, then
slot.insertAdjacentHTML("beforeend",
  `<article class="sk-content card">${card}</article>`);
await reveal(grid);   // (cards − 1) × 70 + 560 ms
grid.querySelectorAll(".sk-skeleton").forEach((s) => s.remove());
sync.disconnect();

      Effect 4 · createDotWireframe()

      Dot wireframe build

      For UI an AI feature returns. A dot field ripples out while the request runs. When the result lands, its real DOM is traced in dots (tiles, text lines, table rules, the chart line), then a scan line hands over to the finished report.

      Use forOne-off generated results. It adds about 2.3 s after the data arrives.

      1. wait(): dot field while the request runs
      2. reveal(): trace the real layout
      3. Scan line hands over to the report
      How the skill wires it
      const wf = createDotWireframe(target);
target.style.minHeight = "330px";
wf.wait();                       // request pending

// result rendered inside target, then
target.append(report);
target.style.minHeight = "";
await wf.reveal(report);         // ~1.5 s trace + 0.8 s scan

      Effect 4 with texts · createDotWireframe(target, { texts: true })

      Dot wireframe build with generation texts

      The same build, narrated. An agent log lists every part as it is traced, the motion CSS is written live from the card's real radii, colours and type, and a step line names each stage. The panels only appear where the page is empty: beside the element, else in a strip under it, else just the step line.

      Use forLaunch pages, demos, onboarding and product videos, where the "built by an agent" story is the point. One element with room around it.

      1. wait(): dot field, the log shows the model thinking
      2. reveal(): the log lists each part, the CSS is typed
      3. Scan line, then the step line shows the done text
      How the skill wires it
      const wf = createDotWireframe(card, {
  texts: true,
  steps: ["Reading the account", "Picking components",
          "Writing styles", "Adding motion"],
  done: "Summary card ready",
});
wf.wait();                       // request pending

// result rendered inside card, then
await wf.reveal(summary);

      The effects are the skeleton-loaders skill's bundled assets, loaded unchanged. Patterns and timings are adapted from transitions.dev by Jakub Antalik.

      With reduced motion turned on, skeletons hold still and every reveal is a 200 ms fade, exactly as the skill ships them.
