Performance Testing

Find what makes software slow before your users do.

Learn to test a web application's performance from both sides. Static testing inspects code, queries and assets without running anything. Dynamic testing runs the system, puts traffic through it and measures what users feel. You practise both on Larkspur Books, a small bookshop app that is slow on purpose.

You'll be able to

  • Turn "it should be fast" into measurable budgets and thresholds
  • Find N+1 queries, missing indexes and heavy assets by reading code, plans and builds
  • Measure page load in the lab with Lighthouse and read Core Web Vitals
  • Write and run load, stress, spike and soak tests with k6
  • Locate a CPU bottleneck in a flame graph and prove the fix
  • Put static and dynamic checks into CI, and report results people can act on
  • Run an acceptance test against agreed criteria and record a go/no-go decision
  • Apply the static checks to your own project, with an agent implementing the fixes

Before you start

Developers and testers who can read JavaScript and SQL and use a terminal. No previous performance testing experience needed.

  • Node.js 22.13 or later
  • A terminal and a code editor
  • Chrome, for Lighthouse and the CPU profiler
  • k6 for chapter 3 (the course also includes a built-in fallback load tool)

Set up the practice app

cd academy/practice/larkspur
npm run seed
npm start   # leave it running in its own terminal; http://localhost:3000
