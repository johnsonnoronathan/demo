パフォーマンステスト

ユーザーより先に、ソフトウェアを遅くしている原因を見つける。

Web アプリケーションのパフォーマンスを両面からテストする方法を学びます。静的テストは何も実行せずにコード・クエリ・アセットを調べ、動的テストはシステムを動かしてトラフィックを流し、ユーザーの体感を測ります。練習には、わざと遅く作られた小さな書店アプリ Larkspur Books を使います。

できるようになること

  • 「速くあるべき」を測定可能な予算としきい値に変える
  • コード・クエリプラン・ビルドを読んで、N+1 クエリ・インデックス不足・重いアセットを見つける
  • Lighthouse でページ読み込みをラボ計測し、Core Web Vitals を読む
  • k6 で負荷・ストレス・スパイク・ソークテストを書いて実行する
  • フレームグラフで CPU のボトルネックを特定し、修正を証明する
  • 静的・動的チェックを CI に組み込み、行動につながる結果を報告する
  • 合意済みの基準で受け入れテストを実行し、Go / No-Go の判断を記録する
  • 自分のプロジェクトで静的チェックを行い、修正の実装はエージェントに任せる

始める前に

JavaScript と SQL が読め、ターミナルを使える開発者とテスター。パフォーマンステストの経験は不要です。

  • Node.js 22.13 以降
  • ターミナルとコードエディタ
  • Lighthouse と CPU プロファイラ用の Chrome
  • 第 3 章用の k6（組み込みの代替ロードツールもあります）

練習アプリを準備する

cd academy/practice/larkspur
npm run seed
npm start   # leave it running in its own terminal; http://localhost:3000
