静态测试

在运行任何东西之前，通过阅读你构建的东西来发现性能问题。

文字稿
  1. 简介
  3. 你将收获什么
  8. 你的工具

静态测试是你能做的最便宜的性能测试。它们阅读代码、查询计划和构建产物，所以不需要服务器、不需要流量，也不需要测试环境。它们只需几秒，因此可以在每次改动时运行，远在任何人察觉变慢之前。

代价是：静态检查只能发现看起来像已知慢模式的问题。它能告诉你某个查询会扫描 200,000 行，却说不出在 50 个用户下这要花多少秒。那是第 3 章的任务。本章中，你将在完全不启动应用的情况下找出 Larkspur 的三个问题，然后用一次简单的请求确认每个修复。

你将收获什么

  • 把计划中的预算变成一项能让构建通过或失败的检查
  • 用 linter 和肉眼在代码中发现 N+1 查询模式，并消除它
  • 阅读 SQLite 查询计划，识别全表扫描，并用索引修复它
  • 找出让页面变重的原因，并把它压到预算以下
  • 知道哪些检查应该在每个拉取请求上运行

你会用到的工具

工具 它读取什么 课
npm run budget 店面加载的文件，对照 budget.json 测量 2.1、2.4
npm run lint:queries 源文件，查找循环中的数据库调用 2.2
npm run explain SQLite 对某个查询的执行计划，无需真正运行 2.3

这三个工具都随练习应用一起提供，无需安装任何东西。
