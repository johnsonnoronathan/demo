什么是测试用例？

逐个字段构建一个测试用例，再对着真实的登录页面手工执行它。

文字稿
  1. 欢迎
  4. 定义
  9. 测试用例的组成
  16. 手工执行
  22. 用例失败时
  27. 小结

学完本课你将能够

  • 说出测试用例的各个字段及其用途
  • 写出足够精确、任何人都能重复执行的测试用例
  • 手工执行测试用例并记录结果

测试用例是对某一个行为的书面、可重复的检查。它写明所处的情境、具体的操作以及你期望的结果，让任何人执行它都能得出相同的结论。

字段

字段 填写内容
ID 稳定且唯一的标识，例如 TC-LOGIN-001。缺陷报告和测试执行记录都会引用它。
标题 被测的行为，用结果的形式表述：“使用有效的邮箱和密码登录成功。”
前置条件 第 1 步之前必须成立的条件：账户、设置、数据、起始页面。
测试数据 具体的输入值。要写 ada@larkspur.test，而不是“一个有效的邮箱”。
测试步骤 编号，每步一个操作，具体到新人也能照做。
预期结果 软件正确时你会观察到什么。要在执行之前确定。
实际结果 实际发生了什么。在执行过程中填写。
状态 通过（Pass）、失败（Fail）、阻塞（Blocked，无法执行）或未执行（Not run）。

模板

ID:              TC-<AREA>-<NNN>
Title:           <behavior> when <condition>
Requirement:     REQ-<NN>
Preconditions:   - ...
Test data:       - ...
Steps:           1. ...
                 2. ...
Expected result: ...
Actual result:   (filled in during the run)
Status:          Pass | Fail | Blocked | Not run

动手试试

为 Larkspur Books 的退出登录链接写一个测试用例。它应该结束会话，并把顾客带回首页。对照上面的字段检查你的草稿：一位从没见过这个网站的同事，能不能不问你任何问题就执行它？

提示

失败是有价值的。 一个写明了精确实际结果的失败用例（“第 6 次尝试仍被允许；账户未锁定”），已经是半份缺陷报告了。

检验理解 · 答对 2/3 即通过

1哪个预期结果写得好？

它写出了可以观察、可以比对的东西。其他选项都会让两名测试人员得出不同的结论。

2预期结果应该在什么时候写？

如果事后再写，你往往会照着实际发生的情况去描述，缺陷就被当成“预期”放过去了。

3第 1 步之前必须已经存在一个客户账户。这应该写在哪个字段？

前置条件描述开始之前系统所处的状态。测试数据列出你要输入或发送的内容。

要点

  • 一个测试用例只检查一个行为，并有 ID 和清晰的标题。
  • 前置条件、测试数据和测试步骤让它可以重复执行。
  • 执行前先确定预期结果，执行后记录实际结果。
  • 一个写明了精确实际结果的失败用例，已经是半份缺陷报告。
