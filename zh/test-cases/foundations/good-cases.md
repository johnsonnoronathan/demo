# 第 1.2 课: 好的测试用例与弱的测试用例

编写测试用例 · 第 1 章: 基础 · 15 分钟

> 让测试用例值得信赖的五个习惯，以及许多团队采用的 Given、When、Then 写法。

**学完本课你将能够:**
- 发现测试用例中含糊的措辞并加以改写
- 运用五个习惯：原子性、独立性、可重复、具体、可追溯
- 用 Given、When、Then 的形式编写场景

## 文字稿: 好的测试用例与弱的测试用例 (1:53)

**0:00 引言.** 两个人测试同一个功能，写出的测试用例可能截然不同。这节课我们来看看，什么样的测试用例才算好。

**0:10 弱用例与强用例.** 这是一个弱的测试用例。测试登录。用一个用户登录。能用。 哪个用户？什么密码？“能用”是什么样子？两名测试人员执行它，可能会得出不同的结论。 这是同一个想法改写后的版本。标题只写一个行为：密码错误时登录被拒绝。 数据是确切的，预期结果是看得见的：出现一条错误提示，并且停留在登录页面。

**0:41 五个习惯.** 好的测试用例都有五个共同的习惯。 原子性：每个用例只测一个行为，失败时只指向一个问题。 独立：每个用例自己准备前置条件，不依赖其他用例先执行。 可重复：同样的输入、同样的步骤，每次都得到同样的结果。 具体：真实的值、可观察的结果，不写“应该能用”。 可追溯：每个用例都能对应回它所检查的需求。

**1:13 Given、When、Then.** 许多团队用 Given、When、Then 的形式来写测试用例。 Given 负责准备环境，也就是前置条件和测试数据。 When 是被测的那一个操作。 Then 是预期结果，要写得可以观察。 这种格式读起来就像日常语言，以后还能直接驱动自动化测试。

**1:35 小结.** 总结一下：用真实的值和可观察的结果代替含糊的措辞。 让每个用例保持原子性、独立、可重复、具体、可追溯。 下一章，我们不再问怎么写用例，而是开始问：应该写哪些用例。

## 课文

好的测试用例无论由谁执行，都会给出相同的结论；当它失败时，它指向的只有一个问题。

## 需要警惕的含糊措辞

| 含糊的写法 | 改写为 |
| --- | --- |
| “一个有效的用户” | `ada@larkspur.test` / `Lark!2026` |
| “能用” | “打开账户页面，显示‘欢迎回来，Ada’。” |
| “应该显示错误” | “表单下方出现‘邮箱或密码不正确’。” |
| “测试购物车” | 每个行为一个用例：添加、移除、修改数量…… |

## 五个习惯

1. **原子性。** 每个用例只测一个行为。如果标题里需要用“并且”，就拆开。
2. **独立。** 不依赖其他用例先执行；自己准备前置条件。
3. **可重复。** 固定的数据，固定的步骤。除非把日期固定下来，否则不要用“今天的日期”。
4. **具体。** 写具体的值和可观察的结果，而不是意图。
5. **可追溯。** 引用对应的需求，例如 `REQ-01`。

## Given、When、Then

```gherkin
Scenario: 错误的密码被拒绝
  Given 存在客户账户 "ada@larkspur.test"
  And 它的密码是 "Lark!2026"
  When 我使用密码 "lark2026" 登录
  Then 我看到 "邮箱或密码不正确"
  And 我仍停留在登录页面
```

每个场景只保留一个 **When**。出现两个操作，通常意味着应该是两个场景。

## 动手试试

改写这个弱用例：*“检查搜索功能是否正常。”* 选择一个行为（例如，搜索“Middlemarch”时该书排在第一位），用 Given、When、Then 的形式写出来。

## Quiz

1. 某个标题写着“加入购物车并结账并使用优惠券”。它违反了哪个习惯？
   a. 可追溯
   b. 原子性
   c. 可重复
   d. 都没有违反，没问题
   Answer: b. 一个用例包含三个行为，失败时你无法知道是哪一个出了问题。应该拆成三个用例。
2. 用例 B 只有在用例 A 先执行并创建了订单时才能通过。应该怎么改？
   a. 总是先执行 A 再执行 B
   b. 把 A 和 B 合并成一个用例
   c. B 在自己的前置条件中准备好所需的订单
   d. 删除用例 B
   Answer: c. 独立的用例可以按任意顺序执行，可以单独执行，也可以并行执行。B 应该自己创建需要的订单。
3. 在 Given、When、Then 中，预期结果写在哪里？
   a. Given
   b. When
   c. Then
   d. Feature
   Answer: c. Given 是准备，When 是那一个操作，Then 是你期望观察到的结果。

## 要点

- 用真实的值和可观察的结果代替含糊的措辞。
- 让每个用例保持原子性、独立、可重复、具体、可追溯。
- Given 是准备，When 是那一个操作，Then 是预期结果。
