# 第 2.1 课: 等价类与边界值

编写测试用例 · 第 2 章: 设计测试用例 · 15 分钟

> 等价类划分和边界值分析：用几个精心挑选的输入代替成千上万个。

**学完本课你将能够:**
- 把一个输入范围划分为若干等价类
- 选出边界值及其相邻值
- 把等价类和边界值转化为一组精简的测试用例

## 文字稿: 等价类与边界值 (1:25)

**0:00 引言.** 应该测试哪些输入？这节课介绍两种技术，把成千上万种可能的输入，变成少数几个好输入。

**0:09 输入太多.** 在 Larkspur Books 的购物车里，一本书可以订购一到十本。 你不可能把每个数字都测一遍。那该怎么选呢？ 把软件应该同等对待的输入归为一组。这些组就叫等价类。

**0:25 每组选一个.** 这里有三个等价类：太少、数量有效、太多。 每个等价类选一个代表值。太少的，选零。 有效的，选五。 太多的，选十五。三个测试用例覆盖三种行为。

**0:41 缺陷藏在边缘.** 但缺陷偏爱边缘。开发者本想写小于等于，却可能写成了小于。 边界值分析就是在每个边界上测一次，再在紧挨着它的外侧测一次。 下限是零和一。 上限是十和十一。 这里的代码写的是数量小于十。只有恰好订购十本的测试才能发现它。

**1:07 得出的用例.** 把这些放在一起，就得到一组精简的测试用例。 每一行都有存在的理由。没有重复，也没有遗漏明显的情况。 只要输入有范围，就可以用这个方法：年龄、价格、姓名长度、日期。

## 课文

等价类划分把软件应该同等对待的输入归为一组，每组只测一个。边界值分析再补上每组的边缘，差一错误（off-by-one）正藏在那里。

## 分步操作

1. 找出规则：*数量必须在 1 到 10 之间*。
2. 列出等价类：小于 1（无效）、1–10（有效）、大于 10（无效）。
3. 每个等价类选一个代表值：0、5、15。
4. 加上每个边界值及其外侧相邻值：0 和 1、10 和 11。
5. 去掉重复项。最终得到六个用例。

## 别忘了其他等价类

无效输入不只是数字。数量输入框可能收到 `-1`、`2.5`、`"three"`，或者什么都没有。每一种都是单独的等价类，有各自的预期提示信息。第 2.2 课会讲到这些。

```js
// 视频中的缺陷
function isValidQuantity(qty) {
  return qty >= 1 && qty < 10;   // 10 被拒绝了
}
// 修复后
  return qty >= 1 && qty <= 10;
```

## 动手试试

Larkspur 礼品卡可以充值 $5 到 $500，金额必须是整数美元。列出等价类和边界值，再为每一个写出预期结果。

## Quiz

1. 某个字段接受 18 到 65 岁。哪组值覆盖了所有边界？
   a. 18, 65
   b. 17, 18, 65, 66
   c. 0, 40, 100
   d. 18, 30, 45, 65
   Answer: b. 每个边界加上紧挨着它的外侧值：下限是 17 和 18，上限是 65 和 66。
2. 为什么一个等价类的中间只测一个值？
   a. 软件应该以相同方式对待其中的每一个值
   b. 中间的值永远不会有缺陷
   c. 可以少打几个字
   d. 测试工具规定每个等价类只能测一个值
   Answer: a. 这正是等价类的含义。如果 5 没问题，6 的表现几乎不可能不同。
3. 代码写的是 qty < 10，但规则是 1 到 10。哪个测试能发现这个问题？
   a. 数量 5
   b. 数量 0
   c. 数量 10
   d. 数量 15
   Answer: c. 只有恰好等于最大值的输入才会触发错误的比较。5、0 和 15 无论哪种写法，结果都一样。

## 要点

- 把软件应该同等对待的输入归为一组，每组测一个。
- 缺陷往往聚集在边缘：测试每个边界值，以及紧挨着它的外侧值。
- 差一错误（off-by-one）的比较，只有恰好落在边界上的值才能发现。
