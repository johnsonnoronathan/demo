等价类与边界值

等价类划分和边界值分析：用几个精心挑选的输入代替成千上万个。

文字稿
  1. 引言
  3. 输入太多
  7. 每组选一个
  12. 缺陷藏在边缘
  18. 得出的用例

学完本课你将能够

  • 把一个输入范围划分为若干等价类
  • 选出边界值及其相邻值
  • 把等价类和边界值转化为一组精简的测试用例

等价类划分把软件应该同等对待的输入归为一组，每组只测一个。边界值分析再补上每组的边缘，差一错误（off-by-one）正藏在那里。

分步操作

  1. 找出规则：数量必须在 1 到 10 之间。
  2. 列出等价类：小于 1（无效）、1–10（有效）、大于 10（无效）。
  3. 每个等价类选一个代表值：0、5、15。
  4. 加上每个边界值及其外侧相邻值：0 和 1、10 和 11。
  5. 去掉重复项。最终得到六个用例。

别忘了其他等价类

无效输入不只是数字。数量输入框可能收到 -1、2.5、"three"，或者什么都没有。每一种都是单独的等价类，有各自的预期提示信息。第 2.2 课会讲到这些。

// 视频中的缺陷
function isValidQuantity(qty) {
  return qty >= 1 && qty < 10;   // 10 被拒绝了
}
// 修复后
  return qty >= 1 && qty <= 10;

动手试试

Larkspur 礼品卡可以充值 $5 到 $500，金额必须是整数美元。列出等价类和边界值，再为每一个写出预期结果。

检验理解 · 答对 2/3 即通过

1某个字段接受 18 到 65 岁。哪组值覆盖了所有边界？

每个边界加上紧挨着它的外侧值：下限是 17 和 18，上限是 65 和 66。

2为什么一个等价类的中间只测一个值？

这正是等价类的含义。如果 5 没问题，6 的表现几乎不可能不同。

3代码写的是 qty < 10，但规则是 1 到 10。哪个测试能发现这个问题？

只有恰好等于最大值的输入才会触发错误的比较。5、0 和 15 无论哪种写法，结果都一样。

要点

  • 把软件应该同等对待的输入归为一组，每组测一个。
  • 缺陷往往聚集在边缘：测试每个边界值，以及紧挨着它的外侧值。
  • 差一错误（off-by-one）的比较，只有恰好落在边界上的值才能发现。
