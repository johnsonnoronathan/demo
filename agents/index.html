Testbench for agents

Every course is readable by machines as well as people. Here is what an agent can use, and how.

Agent prompts on exercises

Each hands-on exercise has a Copy prompt button. The prompt stands on its own: where to work, the steps, how to tell it's done, what to report, and rules such as quoting real command output instead of estimating. Pages without an exercise have no prompt.

You are doing a hands-on exercise from the "Performance Testing" course: Lesson 1.1, "What performance testing measures".

Exercise: Set up Larkspur and take a first measurement
Goal: Get the practice app running and record a baseline for /api/books: query count, p50, p95 and throughput at 10 users.

Project: academy/practice/larkspur (A Node.js 22 bookshop with a storefront and three JSON endpoints over SQLite. No dependencies. Slow on purpose.)
Setup, if not done already:
  cd academy/practice/larkspur
  npm run seed
  npm start   # leave it running in its own terminal; http://localhost:3000

Steps:
1. Run `npm run seed` and confirm it reports 500 authors, 5,000 books, 50,000 reviews and 200,000 orders.
2. Start the app with `npm start` in the background and wait until http://localhost:3000/health returns `ok`.

A Markdown twin of every page

Add .md to a lesson's address to get it as Markdown. Videos become transcripts, animations become numbered steps, screenshots become their descriptions, and exercises keep their full prompt.

A good way to work

Do an exercise yourself first, then let an agent repeat or extend it. Check that every number in the agent's report appears in the output it quotes.
