# Writing Test Cases

> Write test cases anyone can run, and that find bugs.

The foundations of testing, in short lessons. Learn what a test case is and what makes one trustworthy, choose inputs with partitions and boundaries, cover the unhappy paths, explore without a script, turn a written case into an automated test, and keep a growing suite healthy.

Total time: 1 h 45 min

## Chapter 1: Foundations

What a test case is, and what separates a good one from a weak one.

- [Lesson 1.1: What is a test case?](/demo/test-cases/foundations/anatomy.md) (15 min). The parts of a test case, built field by field and then run by hand against a real sign-in page.
- [Lesson 1.2: Good test cases, weak test cases](/demo/test-cases/foundations/good-cases.md) (15 min). Five habits that make a test case trustworthy, and the Given, When, Then shape many teams write them in.

## Chapter 2: Designing test cases

Choose which cases to write with partitions, boundaries and decision tables.

- [Lesson 2.1: Partitions and boundaries](/demo/test-cases/design/partitions.md) (15 min). Equivalence partitioning and boundary value analysis: a few well-chosen inputs instead of thousands.
- [Lesson 2.2: Beyond the happy path](/demo/test-cases/design/negative.md) (15 min). Negative cases, edge cases, and decision tables for rules that combine.
- [Lesson 2.3: Exploratory testing](/demo/test-cases/design/exploratory.md) (15 min). Learn without a script: steer a time-boxed session with a charter, keep session notes, and turn what you find into test cases.

## Chapter 3: Automating and scaling

Turn cases into code, then organise a suite that people trust.

- [Lesson 3.1: From test case to automated test](/demo/test-cases/automation/unit-tests.md) (15 min). Turn a written test case into code with Arrange, Act, Assert, then watch a boundary test catch a real bug.
- [Lesson 3.2: Organizing a test suite](/demo/test-cases/automation/suites.md) (15 min). The test pyramid, traceability to requirements, and keeping a growing suite healthy.
